# 커밋·브랜치 작업 규칙

> 범위: 5개 업무 저장소의 Git 작업 | 상태: 초안 | 근거: 각 저장소의 최근 커밋·브랜치 목록, 업무 루트 `CLAUDE.md`

커밋은 변경한 하위 저장소 안에서, 기능 브랜치에 커밋한 뒤 병합 요청으로 반영한다. 외부 범용 템플릿의 "main/master에 직접 커밋"은 적용하지 않는다.

- 준비: 변경 파일이 어느 저장소(admin·user·cmp·batch·interface)에 속하는지 확인한다.
- 위치: 해당 하위 저장소 디렉터리. 업무 루트는 Git 저장소가 아니다.

1. 사용자가 요청한 경우에만 커밋한다. 자동 커밋하지 않는다(지침·범용 규칙 공통).
2. 현재 브랜치를 확인한다. `main`·`development`에 직접 커밋하지 않고 `feature/<작업명>` 브랜치를 사용한다(관찰).
3. 여러 저장소를 바꿨으면 저장소마다 따로 커밋한다.
4. 커밋 메시지를 아래 형식으로 작성한다.

| 구분 | 형식 | 예 |
|---|---|---|
| 관찰 | `<Type>: <한글 요약>` | `Feat: vCenter 동적 조회 및 멀티 vCenter 지원 추가` |
| 관찰 | `Fix:`·`Refactor:` 등 첫 글자 대문자 타입 | `Fix: TPCF APP명에 '_new' 붙는 이슈 관련 소스 수정` |
| 관찰 | 보안 조치 연계는 항목 번호 접두어 | `F1: 결재 승인/반려/회수 IDOR 수정 ...` |
| 제외 | 범용 템플릿의 `feat(scope): subject` 소문자·영어 형식 | 기존 이력과 다르므로 쓰지 않는다 |

- 자동 생성 커밋(`Update image tag in cicd/...`)과 `Merge branch ...`는 CI·병합 과정의 산물이다. 직접 작성하지 않는다.
- 핵심 변경이 둘 이상이면 본문에 `- ` 목록으로 적는다(제안).
- 성공 기준: `git log -1`에서 대상 저장소·브랜치·메시지 형식을 확인한다.
- 실패 시: 잘못된 저장소에 커밋했으면 push 전 사용자에게 알리고 되돌릴 방법을 확인한다.

근거: `admin`·`user`·`cmp`·`batch`·`interface`의 `git log` 최근 20건, `cmp`의 `git branch -a`(2026-09-29 확인).
