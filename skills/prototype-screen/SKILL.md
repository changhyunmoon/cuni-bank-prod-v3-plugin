# 화면 프로토타입 (HTML 한 파일)

Claude Code에서 `/cuni-bank-v3-prod-plugin-v3:prototype-screen`으로 호출하거나 메인 개발 스킬의 시안 단계에서 적용한다. 아래 상대 링크는 이 SKILL.md 위치 기준이다.

목적은 **백엔드만 없는 완성 화면**을 만드는 것이다. 서버 호출 자리만 샘플 데이터로 대체하고, 레이아웃·컴포넌트 디자인·프런트 동작은 실제로 구현됐을 때와 같아야 한다. 결과물은 브라우저로 바로 여는 HTML 파일 하나이며, 구현 단계에서 이 파일의 script를 옮겨 쓴다.

## 기준

1. [docs 라우터](../../docs/README.md)의 케이스 트리거 표에서 `cases/screen/`의 해당 화면 유형 문서(목록·팝업·조회 조각 등)를 고른다. 대상 모듈 frontend 기준([Admin](../../docs/reference/frontend-admin.md)/[User](../../docs/reference/frontend-user.md)), [참고 화면](../../docs/reference/screen-references.md), [컴포넌트 표준 마크업](../../docs/reference/ui-components.md)을 함께 읽는다. 표·엑셀 등 해당 케이스가 있으면 그 문서도 읽는다.
2. 같은 모듈·유형의 참고 화면 소스와 대상 모듈의 레이아웃 파일(`layout_final/layout_admin.html` / `layout_user.html`), `static/js/datatables/datatables.ex.js`, `static/js/common.js`를 연다.
3. 결과 위치는 [진행 기록 규칙](../develop-screen-feature/references/progress.md)의 작업 폴더다. 플러그인에 작업 결과를 쓰지 않는다.

## 작성

`<작업 폴더>/prototype.html` 하나만 만든다. Thymeleaf 표현식·`layout:`·`th:replace`를 쓰지 않고, 변환 스크립트·fixture·mock 파일·정적 서버를 만들지 않는다.

### 자원과 file:// 보정

- 레이아웃 파일의 `<link>`·`<script>`를 **고르지 말고 같은 순서로 모두** 파일 위치 기준 상대 경로로 옮긴다(예: `../../admin/src/main/resources/static/css/style.css`). 주석 처리된 항목은 넣지 않는다.
- 서버 없이 `file://`로 열리므로 `/`로 시작하는 절대 경로는 깨진다. 다음은 파일 안 `<style>`·`<script>`에서 보정한다.
  - DataTables 언어: 대상 모듈 `static/js/datatables/cultures/Korean.json`의 내용을 `language` 객체로 직접 넣는다.
  - 화면에 보이는 CSS 자원(폰트·아이콘)이 절대 경로라 빠지면 같은 선택자·font-family로 상대 경로를 다시 선언한다.
- ajax·파일 로드는 쓰지 않는다(브라우저가 `file://`의 로컬 파일 요청을 막는다).

### 레이아웃과 컴포넌트

- 헤더·좌측 메뉴·경로 표시는 레이아웃 파일의 실제 마크업을 옮긴다. 메뉴 항목은 대상 메뉴가 보일 정도로 줄여도 된다.
- 본문은 [컴포넌트 표준 마크업](../../docs/reference/ui-components.md)과 참고 화면의 구조·클래스만 쓴다. 검색 영역·기간·select·버튼·표·팝업·폼을 임의 마크업으로 만들지 않는다.
- 새 클래스·새 인라인 style·별도 `<style>` 규칙을 만들지 않는다. 표준에 없는 표현이 필요하면 참고 화면 → 같은 모듈 기존 화면 순서로 찾고, 그래도 없으면 사용자에게 제안해 확정한 뒤 사용하고 제출 시 카탈로그 추가 대상으로 알린다.
- 기간 검색이 있으면 [기간 검색 가이드](../../docs/cases/screen/period-search.md)의 **A. 날짜** 또는 **B. 날짜·시간** 중 하나로만 만든다. 요구사항(`requirements.md`)에 정해진 방식을 쓰고, 정해지지 않았으면 작성 전에 가이드의 기준으로 추천안을 붙여 사용자에게 둘 중 하나를 고르게 한다. 고른 방식의 마크업·달력 초기화·기본 기간·시작>종료 검증을 그대로 넣고, 선택한 방식을 제출 시 함께 알린다.
- 문구는 화면에 보일 한글을 쓰고, 기존 자료사전에 같은 용도의 값이 있으면 그 값과 같게 쓴다.

### 표

- 실제로 쓸 공통 함수(`grid`·`exGrid`·`emptyGrid` 등, [DataTables 선택](../../docs/cases/table/table-setup.md))의 옵션을 `datatables.ex.js`에서 그대로 가져와 `$(selector).DataTable(...)`로 초기화한다. pageLength·pagingType·dom·lengthMenu·select·order·colResize 등 표시 옵션을 바꾸거나 빼지 않는다.
- 서버 페이징 옵션만 `bServerSide: false`, `ajax` 대신 `data: <샘플 행>`으로 바꾼다. 샘플 행은 페이징·정렬·말줄임·빈 결과를 확인할 만큼 넣는다.
- 화면에서 추가하는 옵션(`columns`, `columnDefs`, 선택 방식 등)은 실제 구현에서 공통 함수에 넘길 값과 같게 둔다.

### 동작

- 프런트에서 끝나는 동작은 실제와 같게 구현한다: 입력 검증과 `$.alert`·`$.confirm`, 날짜 입력(기간 검색 가이드의 선택한 방식), 팝업 열기·닫기, 탭 전환, 행 선택과 미선택 알림, 브라우저에서 만드는 엑셀, 좌우 연동, 초기화.
- 팝업은 같은 파일 안에 실제 팝업 마크업(`popup-head`/`popup-body`/`popup-foot`)으로 두고 bPopup으로 연다. 실제 구현에서는 `showPopup` 등 공통 함수로 바뀐다는 주석을 남긴다.
- 서버 호출이 들어갈 자리(목록 조회·저장·삭제 등)는 `// [프로토타입] 서버 호출 대체` 주석을 붙인 함수로 모아 샘플 데이터 반환·성공 처리만 한다. 검색은 샘플 행을 조건으로 걸러 보여 준다. 그 밖의 코드에 샘플 데이터나 서버 대체 로직을 섞지 않는다.
- 권한별 버튼 노출처럼 서버가 결정하는 것은 기본 상태로 보여 주고 주석으로 표시한다.

### 스크립트 구조

구현에서 그대로 옮길 수 있도록 [공통 작성 순서](../../docs/cases/screen/new-screen.md)를 따른다: 상태 선언 → ready(이벤트 연결·최초 목록 생성) → 목록 함수 → `searchData()` → 동작 함수 → 보조 함수. 이벤트는 한 곳에서 한 번 연결하고 같은 버튼에 `onclick` 속성을 함께 쓰지 않는다.

## 확인과 제출

- 작업 폴더에서 파일을 `file://`로 직접 열어(다른 폴더로 옮기면 상대 경로가 깨진다) 다음을 확인하고 필요하면 스크린샷을 남긴다.
  - 콘솔 오류 0건, CSS·JS·언어 문구 로딩.
  - 표 페이징·건수 선택·정렬·선택, 검색·초기화, 빈 결과, 검증 알림, 팝업 열기·닫기, 날짜 입력 등 요청된 동작.
  - 배치·정렬·간격·넘침.
- 파일에 쓴 class를 모두 대상 모듈 `static/css`와 [컴포넌트 표준](../../docs/reference/ui-components.md)·참고 화면에서 Grep으로 찾아 없는 것이 없는지 확인한다.
- 아래 **실제 화면 비교**를 마친 뒤에만 제출한다. 소스 마크업 대조로 대신하지 않는다.
- 사용자에게 파일 경로, 확인한 내용, 비교한 실제 화면과 남은 차이(샘플 데이터 차이 외에는 없어야 한다), `[프로토타입]`으로 대체한 서버 동작 목록, 표준에 없어 새로 정한 컴포넌트를 짧게 제시한다. 메인 흐름에서는 화면 승인을 요청하고 대기한다.

## 실제 화면 비교

프로토타입은 로컬에서 실행한 실제 화면과 나란히 비교하며 수정한다. 모듈·포트·컨텍스트는 [프로젝트 지도](../../docs/foundation/project-map.md), 실행 명령은 [빌드·로컬 실행](../../docs/foundation/build-and-run.md)을 따른다.

1. **서버 확인**: 대상 모듈(admin `http://localhost:20290/admin` 또는 user `http://localhost:20190/user`)과 로그인·데이터에 필요한 cmp(`localhost:20590`)가 응답하는지 확인한다. 이미 떠 있으면 그대로 쓴다.
2. **기동**: 떠 있지 않으면 cmp → 대상 모듈 순서로 `local` 프로필 `bootRun`을 백그라운드로 실행하고 기동 로그에서 포트 수신을 확인한다. 자격증명·truststore 값은 사용자 환경 변수를 쓰고 기록하지 않는다.
3. **VPN 안내 후 대기**: local 프로필은 내부망(Nexus `10.3.200.51`, cmp DB `10.3.200.50` 등)을 쓰므로 VPN이 필요하다. 기동 전 `Test-NetConnection 10.3.200.50 -Port 5432`가 실패하거나, 기동이 내부망 연결 실패(connect timed out, Connection refused, UnknownHost, Nexus 의존성 다운로드 실패 등)로 멈추면 **"VPN을 켜 주세요. 켜신 뒤 알려 주시면 서버를 다시 띄워 비교를 이어 가겠습니다."**라고 안내하고 대기한다. 진행 기록이 있으면 상태를 `needs-input`(VPN 대기)으로 남긴다. 비교를 건너뛰거나 소스 대조로 대신하지 않는다. VPN과 무관한 실패(JDK·Gradle·자격증명 누락 등)는 원인과 필요한 조치를 알리고 대기한다.
4. **로그인**: Chrome(Claude in Chrome)에서 실제 화면을 열고, 로그인은 사용자가 직접 하도록 요청한다. 비밀번호를 받거나 입력하지 않는다. `file://` 프로토타입을 열려면 확장 프로그램의 "파일 URL에 대한 액세스 허용"이 필요하다고 안내한다.
5. **비교 대상**: 같은 모듈·유형의 참고 화면, 그리고 프로토타입에 쓴 컴포넌트(팝업·폼 등)의 근거 화면을 연다. 기간 검색은 선택한 방식의 근거 화면(A: 작업 목록 `task/list.html`, B: IP 현황 `ipstatus/list.html`)과 달력 선택 창까지 비교한다. URL은 해당 템플릿을 반환하는 Controller 매핑에서 찾는다.
6. **나란히 비교·수정**: 같은 창 크기에서 실제 화면과 프로토타입의 스크린샷을 찍어 헤더·메뉴·경로, 검색 영역, 기간·select·input 크기와 간격, 버튼 모양·위치, 표 머리글·행 높이·페이징·건수 선택·빈 결과 문구, 글꼴, 팝업과 폼을 하나씩 대조한다. 동작(날짜 선택 창, 행 선택, 팝업 열기·닫기, 알림창)도 실제 화면에서 같은 동작을 해 보고 비교한다. 차이는 프로토타입을 고쳐 없애고 다시 비교한다. 샘플 데이터 내용만 다른 상태가 될 때까지 반복한다.
7. **기록**: 비교한 URL, 창 크기, 스크린샷, 고친 차이를 작업 폴더 `evidence/`에 남긴다. 직접 띄운 서버는 제출 때 실행 중임을 알린다.
- 수정 의견은 같은 파일에 반영한다.
