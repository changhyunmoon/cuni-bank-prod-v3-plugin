# 화면 프로토타입 (HTML 한 파일)

Claude Code에서 `/cuni-bank-v3-prod-plugin-v3:prototype-screen`으로 호출하거나 메인 개발 스킬의 시안 단계에서 적용한다. 아래 상대 링크는 이 SKILL.md 위치 기준이다.

목적은 **실제 개발 전에 화면 배치·구성·디자인을 확인**하는 것이다. 결과물은 브라우저로 바로 여는 HTML 파일 하나다. 실제 템플릿·fragment·API 구조는 구현 단계에서 만든다.

## 기준

1. [docs 라우터](../../docs/README.md)의 케이스 트리거 표에서 `cases/screen/`의 해당 화면 유형 문서(목록·팝업·조회 조각 등)만 고른다. 대상 모듈 frontend 기준([Admin](../../docs/reference/frontend-admin.md)/[User](../../docs/reference/frontend-user.md))과 [참고 화면](../../docs/reference/screen-references.md)을 함께 읽는다. 표·엑셀 버튼 등 배치에 영향을 주는 케이스가 있으면 해당 문서의 배치 관련 부분만 확인한다.
2. 같은 모듈·유형의 참고 화면 소스를 열어 레이아웃 구조, CSS 클래스, 검색·버튼·표 배치를 확인한다.
3. 결과 위치는 [진행 기록 규칙](../develop-screen-feature/references/progress.md)의 작업 폴더다. 플러그인에 작업 결과를 쓰지 않는다.

## 작성

`<작업 폴더>/prototype.html` 하나만 만든다.

- 레이아웃(헤더·좌측 메뉴·경로 표시)과 화면 본문을 이 파일에 **직접 HTML로 작성**한다. Thymeleaf 표현식·`layout:`·`th:replace` fragment를 쓰지 않고, 변환 스크립트·fixture·mock 파일·정적 서버를 만들지 않는다.
- 디자인은 대상 모듈의 기존 CSS를 상대 경로 `<link>`로 참조해 실제 화면과 같게 보이게 한다(예: `../../admin/src/main/resources/static/css/style.css`). 클래스 이름과 요소 구조는 참고 화면을 따른다. 필요한 최소 스타일만 파일 안 `<style>`에 둔다.
- 서버 없이 `file://`로 열리므로 `/admin/...`처럼 `/`로 시작하는 절대 경로 자원은 쓰지 않는다(로컬 디스크 루트로 해석되어 깨진다). CSS·이미지·JS는 파일 위치 기준 상대 경로로만 연결한다. 기존 CSS 안의 절대 경로 폰트 등이 빠지는 것은 배치 확인에 영향이 없으면 그대로 둔다.
- ajax·파일 로드는 쓰지 않는다(브라우저가 `file://`의 로컬 파일 요청을 막는다). 프로젝트 공통 grid(`$.fn.dataTable.grid`)처럼 서버 호출이나 언어 파일을 부르는 함수 대신, 참고 화면과 같은 클래스의 표에 샘플 행을 직접 넣는다.
- 문구는 화면에 보일 한글 문구를 그대로 쓰고, 표·목록에는 배치 판단에 충분한 샘플 행 몇 개를 직접 넣는다.
- 스크립트는 배치 확인에 필요한 동작(테이블 전환, 탭·팝업 열기, 열 수에 따른 표 모양 등)만 파일 안 `<script>`로 짧게 넣는다. 서버 호출·검증·오류 처리 같은 실제 로직은 만들지 않는다.
- 레이아웃 공통 부분은 화면 판단에 필요한 만큼만 넣는다(예: 메뉴는 대상 메뉴가 보일 정도).

## 확인과 제출

- 브라우저로 파일을 직접 열어 배치·정렬·간격·넘침·요청된 상태(빈 결과 등)를 확인하고, 필요하면 스크린샷을 남긴다.
- 서버 없이 파일을 직접 열어(`file://`) CSS 로딩과 콘솔 오류를 확인한다. 파일을 다른 폴더로 옮기면 상대 경로가 깨지므로 작업 폴더에서 연다.
- 사용자에게 파일 경로와 확인한 내용, 프로토타입이 보여주지 않는 부분(서버 데이터·권한·실제 동작)을 짧게 제시한다. 메인 흐름에서는 화면 승인을 요청하고 대기한다.
- 수정 의견은 같은 파일에 반영한다.
