# 코드에서 지식 항목 추출

업무 저장소의 특정 모듈·기능에서 반복되는 구조와 규칙을 컨벤션으로 정리한다. 코드는 읽기만 한다. 항목 형식은 [SKILL.md 3단계](../SKILL.md#3-추출)를 따른다.

## 탐색 순서

1. **범위 확정.** 저장소, 상대 경로, 정리할 기능(예: "목록 조회 API", "등록 팝업 저장 흐름")을 정한다. [프로젝트 지도](../../../docs/foundation/project-map.md)와 대상 모듈 구조 문서로 위치를 확인한다.
2. **기존 문서 확인.** 라우터에서 같은 주제의 문서가 있으면 먼저 읽는다. 이미 문서화된 내용은 다시 추출하지 않고 차이만 찾는다.
3. **대표 파일 선정.** 같은 역할의 파일을 검색해 3~5개를 고른다. 선정 이유(최초 작성·최근 표준 화면·사용자 지정)를 남긴다.
4. **흐름 추적.** 화면 → 포탈 Controller → Proxy → CMP Controller → Service → Support/Repository/Mapper 중 범위에 해당하는 계층을 따라간다.
5. **패턴 추출.** 아래 관점별로 공통점을 적는다.
6. **빈도 확인.** 패턴마다 같은 범위에서 따르는 파일 수와 따르지 않는 파일 수를 검색으로 센다.

## 관점

| 관점 | 확인할 것 |
|---|---|
| 구조 | 파일 위치, 계층 책임, 클래스 분리 방식 |
| 명명 | 클래스·메서드·URL·템플릿·JS 함수 이름 규칙 |
| 호출 | 공통 함수·래퍼 사용, 요청·응답 형식, 페이징 |
| 데이터 | DB 접근 기술, 트랜잭션 위치, 사용자별 데이터 범위 |
| 오류 | 예외 처리·변환 위치, 화면 오류 표시 |
| 표시값 | 자료사전·코드사전·설정 조회 방식 |

## 기록 규칙

- 코드에서 나온 항목의 성격은 **관찰**이다. 사용자가 명시적으로 표준으로 지정한 항목만 지침이다.
- 근거는 `저장소:상대 경로`와 클래스·메서드로 적는다. 로컬 절대 경로는 쓰지 않는다.
- 내용에 빈도를 함께 적는다. 예: "검색한 Support 12개 중 10개가 `createPageRequest` 사용". 전체를 검색하지 않았으면 '대표 파일 기준'이라고 쓴다.
- 패턴에서 벗어난 코드, 중복 이벤트·동명 함수 같은 결함은 별도 항목으로 만들고 "복사하지 않을 기존 패턴" 후보로 표시한다. 기존 결함을 표준으로 만들지 않는다.
- 코드 예시는 꼭 필요할 때 항목당 하나, 10줄 이내로 남긴다.
- 빌드·테스트·실행을 하지 않았으면 '실행 미검증'을 항목 또는 소스 기준 기록에 남긴다.
