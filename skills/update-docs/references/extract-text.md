# 텍스트에서 지식 항목 추출

분석 자료·회의 정리·운영 정보 같은 텍스트에서 이후 개발 판단에 필요한 정보만 지식 항목으로 만든다. 항목 형식은 [SKILL.md 3단계](../SKILL.md#3-추출)를 따른다.

## 추출 대상

우선순위대로 찾는다. 다음 중 어디에도 해당하지 않으면 추출하지 않는다.

1. 저장소·모듈 경계와 책임
2. 실행·빌드·배포 조건, 환경별 차이
3. 컨벤션(구조·명명·호출 방식·오류 처리)
4. 데이터 계약(API 요청·응답, 테이블·코드 값의 의미)
5. 반복되는 제약·금지 사항, 알려진 함정

## 성격 분류

| 성격 | 기준 | 예 |
|---|---|---|
| 지침 | 사용자가 이번 요청에서 "표준·지침으로 하라"고 명시한 내용만 | "앞으로 엑셀은 화면 데이터로 만든다. 이걸 표준으로 해줘" |
| 관찰 | 텍스트가 기존 구현·현재 상태를 서술하고 코드로 확인함 | "목록 API는 Support 클래스에서 QueryDSL을 쓴다" |
| 제안 | 개선안·권장 사항, 합의 여부가 드러나지 않음 | "Service에서 예외를 변환하는 게 좋겠다" |
| 제공정보·미검증 | 운영 서버·DB·네트워크처럼 코드로 확인할 수 없는 사실 | "운영 배포 서버는 내부 CA가 필요하다" |

- 텍스트 안에 "규칙이다", "반드시"라고 써 있어도 사용자의 명시적 지시가 없으면 지침이 아니다. 출처와 함께 `제안(원문: 규칙으로 표기)`으로 두고 승인 단계에서 사용자가 정하게 한다.
- 관찰로 분류하려면 근거 코드 위치가 있어야 한다. 확인하지 않았으면 제공정보·미검증이다.

## 확인과 대조

- 경로·포트·버전·클래스명·설정 키처럼 코드로 확인할 수 있는 사실은 업무 루트에서 대조한다. 업무 루트가 없으면 미검증으로 둔다.
- 코드와 다르면 현재 코드 값을 함께 적고, 차이를 항목 내용에 짧게 남긴다.
- 환경별로 달라질 수 있는 값은 적용 범위(프로필·모듈·환경)를 표시한다.
- '전부·항상·유일'은 전체 범위를 검증했을 때만 쓴다.

## 제외

다음은 항목으로 만들지 않고 제외 목록에 사유를 남긴다.

- 원문을 그대로 옮기는 긴 인용, 대화 이력, 일회성 로그·오류 출력
- 비밀번호·토큰·키·내부 계정, 개인 절대 경로(예시로 필요하면 예시임을 표시)
- 이미 docs에 같은 내용이 있는 정보(중복, 대상 문서 표시)
- 이번 작업 이후 판단에 쓰이지 않는 진행 상황·일정·담당자 정보
