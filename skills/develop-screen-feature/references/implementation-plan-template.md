작성 규칙:

- 1절: 모듈마다 `git branch --show-current`와 `git branch -a`에서 작업명·화면명 관련 브랜치를 확인하고, 있으면 `git log`로 내용을 보고 재사용·참고·무관을 판단한다. `main`·`development`에 직접 구현하지 않는다([커밋·브랜치 규칙](../../../docs/foundation/commit-conventions.md)).
- 2절: 디자인 기준 화면의 템플릿을 반환하는 Controller부터 아래로 따라간다. [기능 연결 지도](../../../docs/reference/feature-map.md)에 없는 기능을 추적했으면 완료 보고에서 지도 추가를 제안한다.
- 3·4절: [시안의 서버 호출을 API 계약으로](../../../docs/cases/backend/screen-api-contract.md)를 따른다. 시안과 이름이 다르면 시안을 고칠 대상으로 9절에 적는다.
- 8절의 시나리오는 5단계 verification.md에서 그대로 결과를 채운다.
